# ANAHAT AI Engine

Technical implementation of the ANAHAT assessment engine around the existing architecture and immutable validated KB.

## Run

```bash
pip install -r requirements.txt
cp .env.example .env
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

The default LLM is the local Ollama model configured by `LOCAL_LLM_URL` and
`LOCAL_LLM_MODEL`. Gemini and OpenRouter are optional fallbacks; set their keys
only if you want those remote providers enabled. Keep the local model available
in Ollama (`ollama pull llama3:latest`).

Qdrant must be running at `QDRANT_URL` for retrieval. BGE-M3 uses
`BAAI/bge-m3` with 1024-dimensional normalized embeddings; the model and Qdrant
client are loaded lazily and reused by the app.

For development reloads, restrict the watched path to application source so a
virtual environment is never scanned:

```bash
python -m uvicorn app.main:app --reload --reload-dir app --host 127.0.0.1 --port 8000
```

## Tests

```bash
python -m pytest -q
python -m compileall -q app ingestion scripts
python scripts/verify_kb_integrity.py
```

The technical test suite covers structured LLM output validation/failure, negative and historical evidence, candidate/evidence separation, ambiguity, contradiction, deterministic scoring, seven-chakra evaluation, ten-quadrant coverage, safety routing, Qdrant adapter behavior, raga governance, and therapist prescription approval.

Passing technical tests are **not** clinical/domain validation.

## Environment

See `.env.example`. Local extraction uses Ollama's schema-constrained chat
endpoint. Optional Gemini uses the official `google-genai` SDK; OpenRouter uses
the OpenAI-compatible API. API secrets are never stored in source code.

## Adaptive questions

After each answer, the local LLM words one patient-specific follow-up question (for example
"What exactly does your brother pressurize you about?") on top of the KB/RAG question, which is
kept as the fallback. Backend validators reject chakra words, diagnosis, leading or duplicate
questions; answers still go through the unchanged evidence and scoring pipeline. See
`docs/ADAPTIVE_QUESTIONS.md` and try it with `python scripts/try_adaptive_question.py`.

## KB immutability

`knowledge_base/ANAHAT_KnowledgeBase_v3` is read-only from the engine's perspective. No canonical KB file is rewritten, normalized in place, or generated by the application.
